## HIRMOS integration invariants

These invariant statements are projected into tool-specific integration surfaces. They do not replace `_hirmos/AGENTS.md` or HIRMOS core command authority.

- Detailed user instructions are scope input, not implementation authorization.
- `hirmos start` is non-implementation and must end at a governed baseline checkpoint before product/source edits.
- `hirmos continue` must classify and gate before it codes.
- If implementation units are required or requested, create or revise the IU plan and stop until IU execution is authorized.
- `hirmos status` is read-only.
- `hirmos close` requires evidence-backed close.
- Carry-forward lifecycle is consolidated in `CARRY_FORWARD.md`; use global `CF-YYYYMMDD-NNN` IDs with source refs.
- Carry-forward resolution uses existing start / continue / close flow as accepted-state maintenance, not a new command.
- Never implement first and backfill HIRMOS artifacts afterward.
