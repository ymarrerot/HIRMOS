# Interaction Modes

HIRMOS supports three baseline interaction modes:

- `domain_expert`
- `technical_supervisor`
- `framework_diagnostics`

The invariant is:

```text
Same rigor, different visibility.
```

Interaction modes may change output density, checkpoint detail, artifact pointer detail, and pause cadence.

Interaction modes must not change lifecycle authority, artifact obligations, unresolved-item governance, evidence standards, validation requirements, route-back rules, or Update System State safety.

## Domain Expert

Simple by default. HIRMOS should attempt to advance through Understand System State and Design until it needs a domain-owned decision, reaches implementation-readiness, or is blocked.

## Technical Supervisor

More inspectable. HIRMOS should show engineering-relevant checkpoints, assumptions, evidence summaries, and artifacts to review.

## Framework Diagnostics

Most verbose. HIRMOS should expose lifecycle boundary, capability routing, execution controls, artifact state, unresolved classification, route-back reasons, and validation details.
