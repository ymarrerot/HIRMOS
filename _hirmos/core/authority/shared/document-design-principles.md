# Document Design Principles

## Purpose

Define shared human-facing document quality principles that apply wherever HIRMOS publishes guidance or explanation for humans.

This file is a quality-principles file. It is not part of the main folder-discipline system.

## Human-first clarity

Documents should be readable by humans first. Favor direct language, visible structure, and a clear main message.

## Progressive depth

A document should let the reader understand the basics before needing the deeper details.

## Clear ownership

A document should own one clear job and avoid competing with a stronger authoritative source.

## Pillar and cluster shape

Use pillar-and-cluster thinking when it improves navigation:
- pillar pages orient
- supporting pages deepen

## User-facing language

Prefer concrete language that helps the reader understand what to do, read, or inspect next.

## Stable references

When a document points to deeper doctrine, use stable rooted references so readers can move cleanly to the authoritative source.

## Honest scope

A document should be honest about whether it is:
- guidance
- doctrine
- example
- local operational method

## Separation of concerns inside the document

Sections inside a document should not blur multiple jobs when a cleaner structure would improve readability or reduce drift.
